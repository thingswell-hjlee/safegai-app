# 모바일앱 사양서 [트랙 B 보강] — 프론트엔드 UX 디자인 · 백엔드 연동 설계 (v1.0)

> UI 기획서(화면 정의)와 `spec-b.md`(AWS 백엔드)를 잇는 구현 참조.

## 1. UX 디자인 원칙

- **3초 이해**: 앱을 연 지 3초 안에 '지금 현장이 안전한가'. 홈 최상단은 항상 StatusBanner.
- **한 화면 한 결정**: 각 화면 주 행동 1개. 이벤트 상세의 주 버튼은 '조치 시작' 하나.
- **색이 곧 심각도**: 심각도 4색을 장식에 쓰지 않음. 일반 UI는 네이비·회색조.
- **상태 비은폐**: 네트워크 3상태·데이터 신선도·전송 대기를 항상 표시. 조용한 실패 금지.
- **엄지 조작**: 주 행동 버튼 하단 고정, 최소 터치 타깃 48dp.

페르소나: 시설 관리자(수시 확인+조치 주체, 동선의 90%) / 직업훈련교사(환경·재실 조회) /
운영 책임자(주간 요약, 에스컬레이션 푸시만).

## 4. 인터랙션·접근성

- 당겨서 새로고침: 모든 목록·현황. 자동 갱신은 홈·환경 30초(포그라운드만).
- 푸시 딥링크: 탭→M5 직행. 미로그인 시 로그인 후 원래 목적지(pending deep link).
- 조치 전이: 연타 방지(응답까지 disabled). 409 → 'OOO님이 조치 중' 안내+갱신.
- 파괴적 동작 없음. 확인 대화상자는 로그아웃 1곳.
- 모션: 전환 슬라이드 200ms. 경보 수신은 배너 색 전환만 — **점멸·진동 애니메이션 금지**(불안 유발 방지).
- 접근성: 글꼴 배율 1.3배 무깨짐 / 심각도는 색+아이콘+문구 3중 / EventCard contentDescription("위험, 오븐 전면 접근 감지, 14시 3분, 미처리") / 대비 텍스트 4.5:1·배지 3:1.

## 5. 화면 상태별 UX

### 5.1 데이터 4상태 (전 화면 공통)

| 상태 | 표시 | 규칙 |
|---|---|---|
| 로딩 | 스켈레톤(스피너는 당겨새로고침만) | 0.3초 미만 응답은 스켈레톤 생략 |
| 빈 데이터 | '오늘 발생한 이벤트가 없습니다'+마지막 확인 시각 | 빈 상태는 정상 — 오류처럼 보이게 하지 않음 |
| 오류 | '불러오지 못했습니다'+[다시 시도]+원인 한 줄 | 자동 재시도 1회 후 표시. 기술 메시지 노출 금지 |
| 부분 실패 | 실패한 카드만 ErrorState | 홈 요약 실패가 목록을 가리지 않게 |

### 5.2 네트워크 3상태 배너

`network-modes.md`의 ONLINE(무배너) / LOCAL_VIEW(파랑 '조회만 가능', WebView 보기 전용,
조치 버튼 **숨김**) / ISOLATED(회색 전면 안내+캐시 '이전 정보'+[다시 연결])를 그대로 구현.
모드 선택 UI 금지, 판정은 헬스체크만.

## 6. 백엔드 연동 설계

### 6.1 Cognito 인증 시퀀스

```
[최초] Amplify Auth: 이메일+비밀번호 → 임시비밀번호 변경(1회)
  → idToken(1h)+accessToken(1h)+refreshToken(30d)
  → Keychain/Keystore 보관 (AsyncStorage 평문 금지)
  → cognito:groups로 역할 판정: admin|teacher|operator|maintainer
[자동] 앱 시작 → refreshToken 유효 → 갱신 → 홈 직행
[만료] 401 → 인터셉터 1회 갱신 재시도 → 실패 시 로그인(원래 화면 복귀 예약)
[로그아웃] 토큰 폐기 + DELETE /push/token + Keychain 삭제
```

### 6.2 API 클라이언트 (단일 모듈 api/client.ts)

- axios 인스턴스 1개. baseURL=API Gateway. 타임아웃 8초. Bearer idToken 자동 첨부.
- 재시도: **GET만 1회**(1초 후). POST/PUT 재시도 금지 — 대신 멱등키(clientRequestId).
- 동시성: 상태 전이는 If-Match(버전) → 409 시 최신 재조회·UI 갱신.
- 로깅: 개발 빌드만 상세. 운영은 오류 코드·소요시간만(토큰·개인정보 금지).
- 엔드포인트는 spec-b.md 4장 그대로 — 재정의 금지.

### 6.3 캐시·상태관리

```
Zustand 스토어 3개 (Redux 도입 금지 — 과설계):
  authStore / eventStore(낙관 갱신·실패 롤백) / envStore
react-query: staleTime 30s(홈·환경) / 5m(통계)
마지막 성공 응답 → AsyncStorage 스냅샷 → ISOLATED '이전 정보' 표시
캐시 저장은 표시 데이터만(토큰·개인정보 제외)
```

### 6.4 에러 → 사용자 문구 매핑

| 발생 | 문구 | 부가 동작 |
|---|---|---|
| 타임아웃·네트워크 | 연결이 원활하지 않습니다 | 재시도 1회 → 반복 시 헬스체크·모드 재판정 |
| 401(갱신 실패) | 다시 로그인해 주세요 | 세션 정리 |
| 403 | 이 기능의 권한이 없습니다 | 역할별 버튼은 원래 숨김 — 403 노출은 버그 로깅 |
| 409 | 다른 관리자가 먼저 처리했습니다 | 최신 상태 재조회 |
| 5xx | 잠시 후 다시 시도해 주세요 | CloudWatch 대상 — 앱은 재시도 버튼만 |
| GW 헬스 실패 | 현장 연결 확인 중 | LOCAL_VIEW/ISOLATED 판정 진입 |

## 7. 푸시 수명주기

`push-policy.md` 5장 그대로. 포그라운드=인앱 배너 3초+목록 갱신,
백그라운드=시스템 알림→딥링크. iOS 확장 시 변경은 토큰 계층(APNs via FCM)뿐.

## 8. 성능·수용 기준

| 항목 | 기준 |
|---|---|
| 콜드 스타트→홈 | ≤3초(캐시 우선 표시 후 갱신) |
| 푸시 탭→상세 | ≤2초 |
| 발생→푸시 도달 | ≤10초(정상망) |
| 조치→반영 | 낙관 즉시+서버 확정 ≤2초 |
| 크기·메모리 | APK ≤40MB, 상주 ≤300MB |

수용 시험: B1 sim DANGER→푸시→딥링크→조치 3단계 / B2 동시 조치 409 /
B3 토큰 만료 자동 갱신(무감지) / B4 기내모드=ISOLATED+캐시, 크래시 0 /
B5 인터넷 불가 WiFi=LOCAL_VIEW 보기 전용 / B6 배율 1.3+TalkBack /
B7 계정 전환 시 이전 계정 푸시 미수신 / B8 INFO 끔 설정 시 DANGER만 수신.
