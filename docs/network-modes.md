# network-modes — 네트워크 3상태 계약 (v1.1 · 동결)

> 원본: 「모바일앱 네트워크 동작 사양 지침서 v1.1」. 앱·게이트웨이 공통 준수.

## 0. 불변 원칙 5

1. **P1** 쓰기(조치·설정)는 클라우드 단일 경로. 로컬 쓰기 경로를 만들지 않는다.
2. **P2** 모드는 자동 판정. 사용자에게 로컬/인터넷 **모드 선택 UI 금지**.
3. **P3** 상태와 데이터 기준시각을 상시 표시. 조용한 실패 금지.
4. **P4** 현장 안전(경광등·부저)은 앱·인터넷·AWS와 무관하게 게이트웨이 단독 동작.
5. **P5** 푸시는 비보장 전제. 안전망은 서버 에스컬레이션.

## 1. 앱 상태 3종

| 상태 | 조건 | 동작 |
|---|---|---|
| ONLINE | 클라우드 헬스체크 통과 | 전 기능 |
| LOCAL_VIEW | 클라우드 불가 + 게이트웨이(:8080) 도달 | 게이트웨이 로컬웹 WebView **보기 전용**. 조치 버튼 숨김(비활성 아님 — 숨김). 파랑 배너 |
| ISOLATED | 둘 다 불가 | 전면 안내 + 마지막 수신 캐시('이전 정보' 워터마크) + [다시 연결] |

## 2. 판정 절차 (OS 표시 신뢰 금지)

```
1) 클라우드 헬스체크 (3초 타임아웃)
2) 실패 시 generate_204 등으로 '서비스 점검(AWS 장애)' vs '내 연결 문제' 구분
   → AWS 장애면: "서비스 점검 중 — 현장 안전은 정상" 전용 화면 (ISOLATED 아님)
3) 게이트웨이 :8080/api/health 체크 → 도달 시 LOCAL_VIEW, 불가 시 ISOLATED
전환은 자동. 복귀 시 배너 자동 해제.
```

## 3. 상황 5종 매핑

| 상황 | 환경 | 앱 상태 | 특이 |
|---|---|---|---|
| A | 현장 WiFi(인터넷×) + LTE○ | ONLINE | '현장 연결 지연' 배너(heartbeat 근거) |
| B | 현장 WiFi(인터넷×) + LTE× | LOCAL_VIEW | 보기 전용 |
| C | WiFi(인터넷○) + LTE○ | ONLINE | 정상 |
| D | WiFi(인터넷○) + LTE× | ONLINE | WiFi 범위 내 |
| E | AP 장애 + 유선 정상 | ONLINE | 현장 실시간 유지 + 'AP 장애' FAULT (게이트웨이가 AP ping 30초×3회 감지) |

## 4. 감시 사슬 — "감시는 항상 한 단계 바깥이"

```
센서·AP·스위치  ← 게이트웨이 (로컬 ping/health 30초)
게이트웨이      ← AWS (heartbeat 60초 + IoT 생명주기 disconnected)
AWS            ← 앱 (헬스체크)
푸시 도달       ← 서버 에스컬레이션
```
감시 실패 = FAULT(회색)로 표시하며, 위험(빨강)과 구분한다.
게이트웨이 자체 장애를 제외한 모든 장애 지점에서 현장 경보는 생존하고,
모든 장애에 감지·통지 경로가 존재해야 한다("조용한 장애 없음" = 완결 조건).

## 5. 정전·장기 오프라인

- UPS 계통 = 게이트웨이 + 스위치 + AP(15~30분). 정전 중 감지·경보·전송·푸시 유지.
- '정전 발생' WARNING 즉시 푸시 → 잔량 저하 2차 통지 → 복전 자동 복구·통지.
- 게이트웨이는 RTC 유지 + 복구 시 NTP 재동기화. 이벤트 seq(단조 순번)로 순서·중복 보장.
- 토큰 만료: 조용한 재인증 시도 → 실패 시 명확한 재로그인 안내.
